# Verification

Every migration should include evidence that the JAX implementation preserves
the original computation.

## Equivalence Checklist

Compare:

- input shapes and dtypes;
- output shapes and dtypes;
- numerical values with explicit tolerances;
- parameter and state updates;
- random behavior under controlled seeds;
- gradients for differentiable objectives;
- error handling or boundary behavior where relevant.

Passing a function once is not the same as preserving semantics.

## Basic Pattern

1. Keep the original implementation importable.
2. Construct deterministic test inputs.
3. Run the original implementation.
4. Run the JAX implementation.
5. Convert JAX arrays to host NumPy arrays for comparison.
6. Compare shape, dtype, and values.
7. Add gradient or state-transition checks when relevant.

For numerical values, start with:

```python
import numpy as np

np.testing.assert_allclose(actual, expected, rtol=1e-5, atol=1e-6)
```

Adjust tolerances for dtype, backend, and algorithmic differences.

## Randomness

JAX uses explicit PRNG keys rather than hidden global random state. A migrated
implementation should make key flow visible and should split keys before
independent random operations. Tests should avoid pretending that PyTorch,
NumPy, and JAX produce identical random streams. Instead, compare deterministic
properties, seeded fixtures, or outputs after injecting controlled samples.

## Gradients

For training code, verify more than the forward pass:

- confirm the loss is scalar where `grad` requires it;
- confirm which arguments are differentiated;
- compare gradients on a tiny deterministic problem;
- verify optimizer updates use the computed gradients and preserve state
  structure.

## Benchmarks

Benchmarking is required before performance claims.

Use:

- warmup runs that exclude first-time compilation;
- stable input shapes;
- realistic workload sizes;
- explicit synchronization, such as `block_until_ready()` on JAX results;
- separate measurements for compilation time when compilation cost matters.

Report hardware, backend, input sizes, dtype, and whether timings include
compilation.

## Paper Context

Phan et al. report that PyTorch-to-JAX translations generated by LLMs often
require human fixes, especially around model definitions, training loops,
JAX-specific constructs, gradients, and optimizer updates. This supports the
policy used here: migration is not complete until behavior is checked against a
reference implementation.

Reference: <https://arxiv.org/abs/2510.09898>
